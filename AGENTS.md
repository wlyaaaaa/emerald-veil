# Emerald Veil project rules

- Product behavior is defined in `docs/product-design.md`; keep it synchronized with material runtime changes.
- The project also owns the approved static Windows desktop/lock-screen selection and cross-machine recovery through `scripts/Set-WindowsBackground.ps1`, defined in `docs/windows-background.md`. This one-shot entry preserves Wallpaper Engine and the Bubbles runtime, keeps machine preimages outside Git, and never locks the session. It does not reopen the rejected cat experiment.
- The supported product entry is `scripts/Set-NativeBubbles.ps1`. Render only the installed `Bubbles.scr /s`, retaining its original glass and complete background composite with full-opacity layering. Never black-color-key native glass: partially black-composited pixels turn into opaque rings. `ShowBubbles=1` and `MaterialGlass=1` are reversible project-owned settings, verified before display. Preserve native animation, colors, collisions and approved radius; do not copy or draw bubble visuals.
- Select the existing Wallpaper Engine material and properties assigned to VDD when its real VDD desktop is rendering; otherwise use VDD's Windows wallpaper/color/fit. Compose that material once on the physical target before native startup. The original renderer takes its entry snapshot; do not advertise live-video transparency. A unique, offscreen, muted Wallpaper Engine pop-out and DWM thumbnail are allowed solely as a source material renderer. Close only that invocation's exact named window, never a desktop instance. No continuous VDD desktop capture, exported video, custom rendering, global stop/play loop or selected-wallpaper mutation.
- Native Bubbles configuration must remain per-user and reversible. The only allowed helper startup is the project's owned direct WinExe Run value (`Emerald Veil Native Bubbles`); never add a scheduled task, shell wrapper, PowerShell wrapper, or second helper. Preserve exact registry value presence, kind, value, and Windows runtime state in the durable preimage.
- `Disable` is the emergency path: it must stop the owned native overlay, clear the project enabled flag, and keep Windows' own screen-saver trigger off even when unrelated Bubbles settings have drifted.
- Do not vendor `Bubbles.scr`, Microsoft assets, or copied Microsoft visual code. Use the Windows-installed system component and verify it exists before configuration.
- Do not add VDD/desktop screen capture, telemetry, networking, persistent activity logging, or general-purpose input hooks. The resident low-level observer is restricted to two product-owned purposes only: (1) the mouse classifier may suppress a `WM_MOUSEMOVE` only when its per-monitor-aware point exactly equals the previous mouse-event point; for idle accounting it may defer one isolated injected nonzero move until a second injected move arrives within 250 ms, while the event itself still reaches the system; and (2) the keyboard observer may record only the input timestamp and consume the exact `Ctrl+Win+E` chord used to start the screen saver, passing every other key through without retaining key contents. Physical movement, a confirmed injected movement stream, buttons, wheel, and all other keyboard input remain normal activity. The observer may retain only the previous pointer point plus minimal injected-sequence, accepted, pending, chord-latch, and latest-classification tick state in memory, with no source-product allowlist or event logging.
- Remote compatibility is architectural: stay on the signed-in user's current desktop, never enter secure desktop/lock state, remain click-through, and never special-case a fixed list of remote-control product names.
- Each launched `Bubbles.scr` must belong to a kill-on-close Job Object. Watchdog exit, crash, restart, input dismissal, and explicit Disable must not leave a renderer that can overlap a later instance.
- A cross-process session lease plus a read-only current-session Bubbles check must refuse a duplicate renderer. Do not kill or take over an existing native instance merely to obtain the lease.
- The repository is public. Never add credentials, machine snapshots, raw logs, private screenshots, local databases, personal paths, or a captured preimage.

- Automatic and explicit displays share one physical-desktop-only policy. VDD, instrument displays, unknown identities and blacked-out targets are excluded. Static wallpaper still covers every monitor. With the physical desktop screen absent, the enabled watchdog waits without drawing a background or launching Bubbles.
- Pause, Disable and meaningful input always outrank preview. A preview lasts at most 15 seconds and must not turn its expiry into an idle relaunch loop. Hide the owned background before native process teardown. Failed starts use 5-second and 30-second cooldowns, then suspend after three failures in one idle episode.
- Keep the installed native /s renderer. Do not add replacement drawing, /t experiments, process injection, Windows binary patches, driver resets or another resident helper. Do not globally disable the installed screen saver as a substitute for completing a repair.
- Status/window health, installed-source parity, real native animation, a real remote client and natural login/reboot are different evidence. State unavailable physical-screen acceptance explicitly. Per-user scripts and startup maintenance must reject Session 0.

- Default delivery state is `NativeBubblesEnabled=1`, direct per-user logon startup present, and session pause=false. Pause is an optional current-session control only and must never become the post-install/default-login state. `Ctrl+Win+E` and tray double-click start the real unbounded-until-input screen saver; the 15-second preview stays a separate action. Reuse the existing low-level keyboard observer for the chord, consume only that exact chord, and wait for full key release plus a bounded stable-input interval before baselining. Do not add a second service/task/hotkey registrar.
